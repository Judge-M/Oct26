# Cue plan and evidence-release boundaries

There are exactly two agenda cues. Introduction: assembled teams before investigation. Exit: actual end of the assisting teams' assignment, even with incomplete analysis. Neither announces evidence delivery or waits for a synthesis ticket. The exit is the only recorded close. There are no prerecorded release injects, post-lunch or midpoint cues.

The controller continues to release evidence automatically through the unchanged [release runbook](../../facilitator-evidence-release.md):

| Dependent | Prerequisites | Released files |
|---|---|---|
| T07 | T06 | identity/late-auth.csv |
| T09 | T08 | server/version-comparison.csv |
| T11 | T10 | hunting/late-inventory.csv |
| T19 | T01 and T05 | network/dlp-body.txt and network/dlp-metadata.json |
| T20 | T07, T09, T11 and T19 | No additional file |

Verify delivery through actual controller diagnostics, task visibility and participant files when troubleshooting a release. Playing audio neither publishes nor proves evidence delivery. Never manually copy vault files, bypass dependencies, award points or invent forensic confirmation to support a narrative beat. Release order can vary.

Use the organizer's actual agenda and mode/readiness procedures. The introduction does not start the clock; the exit does not pause it. At the closing seam stop investigation, verify paused mode through the event runbook, preserve case work and proceed to AAR. A delivery problem is handled through RUNBOOK.md, not a changed narrative outcome.
