# H01 — Consolidate preserved recipes into a portable build pipeline

## Context and prerequisites

Repository: https://github.com/Judge-M/Oct26. Existing native capture, prepared case and desktop are published. No original workstation or old credentials are needed. Read `../EXECUTION.md` and `../CONTINUE-ELSEWHERE.md`. This is a future implementation assignment, not permission to run the archived scripts blindly. It can proceed independently of event infrastructure tasks; it must not block source development or reusing accepted artifacts.

## Read first

- `deployment/expanded/build-history/README.md` and `inventory.json`
- Historical native preparation/packaging, case packaging, desktop export/boot-check/packaging recipes
- `expanded/materialize_native.py`, `expanded/create_autopsy_case.py`, `expanded/prepare.py`

## Implement in small child tasks

1. **H01a — Native records:** parameterize originals, parser results and output release paths. Derive PIDs from acquisition provenance rather than literal 6364/7644. Read EVTX sidecars or provide a Windows-native export command. Never rewrite original times. Verify raw/source hashes and emit new versioned neutral records in a new directory.
2. **H01b — Case packaging:** accept a closed case and evidence directory; verify DB integrity, complete ingest and saved index; emit archive/manifest with correct logical/native distinctions. Reject active/unclean cases and overwrites.
3. **H01c — Desktop preparation:** use an explicit disposable guest provider, configurable build root, verified base/tool inputs and fresh credentials. Port the successful generic-kernel/NoCloud/Solr fixes; exclude superseded steps. Allocate NBD/mounts safely instead of assuming `/dev/nbd0` is free.
4. **H01d — Export and verification:** validate sealing, compact only the stopped owned guest, boot a snapshot offline, verify tools/case and credential gate, then split/hash to a new release. No task may set a validation field without observing that result.
5. **H01e — Orchestration/documentation:** one build configuration links these stages; resumable stage receipts and immutable output inventory. Store optional downloadable dependency closure separately from runtime secrets and never bake build keys into artifacts.

## Acceptance

First recover the existing native files with `expanded.materialize_native` on a second machine or clean environment. Recreate neutral records/case packaging from published inputs with no original absolute paths or hand-edited scratch files. Then test image rebuild on a disposable Linux build host. Compare semantic evidence/tool behavior and record new hashes; do not promise bit-identical VM images or recaptured RAM. Test corrupt input, missing dependency, occupied block device, interrupted packaging and existing destination rejection. Publish only successful versioned outputs and sanitized build records.

## Exclusions and handoff

Do not acquire host memory, recover old private keys, mutate v1 originals, implement AWS event orchestration here, or weaken validation to reuse old success flags. Assign each child to one agent, return changed files/commit/tests/limitations, and stop. Block only environment-dependent stages when build resources are unavailable; continue source/tests independently. Require a focused reviewer for block-device and deletion operations.
