# IRIS exercise controller guide

Use [current operations and recovery](../docs/expanded-operations.md) for commands,
exports and reset procedures, and [deployment](../docs/expanded-deployment.md) for
provisioning. IRIS provides the shared ticket queue; CTFd accepts answers and
shows points. Do not start the legacy rehearsal portal or manually grade reports.

Before starting, verify team identity mappings, desktop access, initial evidence,
question visibility and shared history. Start or pause using ridge.cli; publish
schedule changes with its announce command so every team can see them.

Ticket dependencies control follow-up evidence availability. Do not manually
attach future material, duplicate findings, award points or close native tasks.
Monitor synchronization and use the documented recovery procedure for outages
or abandoned ownership. Recovery retains solved answers and earned points.

Provide free coaching and graduated hints. No report, command acknowledgment or
facilitator sign-off is required for progression. Pause for technical failures
and record problems for rehearsal follow-up.

Keep the vault, answers, credentials, participant work and full audit exports
private. Pause and drain synchronization before the combined IRIS/CTFd/core export.
Run the AAR before preparing a clean run. Full deployment and rehearsal readiness
must be established using the [acceptance record](../docs/expanded-validation.md).
